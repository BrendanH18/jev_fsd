# Agent instructions

## Commands

The local app needs no build. Python runs through `uv` with one runtime dependency, `typesafe-sdk`. The browser loads ES modules and maps Three.js to `static/vendor/three/`. CI packages the static demo with `scripts/build_demo.py`. Ruff (config in `pyproject.toml`) and Biome (`biome.jsonc`; `static/vendor/` and `data/` are left out) lint and format; CI runs both (`.github/workflows/lint.yml`). Biome is the only npm package: `package.json` and `package-lock.json` pin it (Dependabot updates it), so use `npm ci` for the first install (no approval needed in Boat; ask first on this Mac). Biome warnings fail CI as errors do. Fix what they report rather than hand-formatting or silencing a rule; an unused parameter a callback signature needs gets a leading `_`. Node checks that read source with regexes must accept the formatter's line breaks and trailing commas.

```sh
scripts/boat-check.sh [--full] [-- CMD]                     # the checks below in this worktree's Boat sandbox (see Boat)
npm ci                                                      # install the pinned Biome (once)
uv run --locked ruff check && uv run --locked ruff format --check && npm run lint   # lint and format checks
uv run --locked ruff check --fix && uv run --locked ruff format && npm run format   # apply safe fixes and formatting
uv run server.py                                            # serves http://127.0.0.1:8322 (PORT to change)
uv run python -m unittest discover -s tests                 # offline Python tests
uv run python -m unittest discover -s tests -p "test_routing.py"          # one file
uv run python -m unittest discover -s tests -k test_route_never_backs_up  # one test
uv run scripts/fetch_map.py [bbox|preset] [--force]         # build/rebuild a map pack
uv run scripts/verify_jev.py                                # live: committed Jev fixtures and data/snapshots/*.json (costs credits)
node --experimental-default-type=module scripts/bench_node.mjs --features city            # the city suite under Node (server running)
node --experimental-default-type=module scripts/arena_node.mjs --brain jev --set all --record out.json.gz   # challenges and road tests (server running)
node --experimental-default-type=module scripts/arena_node.mjs --replay out.json.gz --check 1     # fail on a failed drive or replay mismatch
```

The main ruleset requires three checks: `Lint and format`, `Demo checks passed` (`demo.yml`) and `Benchmark passed` (`bench.yml`). The last two pass only when every job they `need` passed, so include each new check job in the corresponding gate's `needs`. The benchmark gate includes the [fixed hard city slice](docs/reference/benchmarks.md#hard-city-slice). The demo deployment runs separately on main.

Workflows (`.github/workflows/`) run on GitHub-hosted standard runners (`ubuntu-24.04`) and pin every action to a full commit SHA with a `# vX.Y.Z` comment, which Dependabot keeps up to date. CodeQL is an advanced setup (`codeql.yml`), not GitHub's default setup. The weekly city soak (`soak.yml`) is report-only: a failing leg leaves the run green, and its `Soak summary` job lists the failed routes in the run summary and as warnings (`scripts/soak_summary.py`).

### Checking work

CI is the gate: it runs the full suite once, on the pushed commit, and `main` takes only a commit whose required checks passed. Everything `scripts/boat-check.sh` runs, plain or `--full`, is in CI (`lint.yml` and `demo.yml`'s Python and Node jobs), along with the browser suites, the demo build and the seeded benchmark. Don't run the full suite (`scripts/boat-check.sh` or `--full`) before handing work back.

- While working, run targeted checks on Boat with `scripts/boat-check.sh -- CMD`: the tests that cover the code you changed, and lint for the languages you touched. Each takes seconds on a resumed sandbox:
  ```sh
  scripts/boat-check.sh -- node --experimental-default-type=module scripts/test_parking_reservations.mjs   # one Node check
  scripts/boat-check.sh -- node scripts/node_checks.mjs --jobs 4 scripts/test_free_drive.mjs scripts/test_feature_registry.mjs   # a few, in parallel
  scripts/boat-check.sh -- uv run --locked python -m unittest discover -s tests -p "test_routing.py"     # one Python test file
  scripts/boat-check.sh -- "uv run --locked ruff check && uv run --locked ruff format --check"          # Python touched
  scripts/boat-check.sh -- npm run lint                                                                 # JavaScript touched
  scripts/boat-check.sh -- node --experimental-default-type=module scripts/build_jev_fixtures.mjs --check   # sensing, candidates or Jev wording touched
  scripts/boat-check.sh -- uv run --locked python -m unittest discover -s tests -p "test_doc_links.py"  # docs touched
  ```
- CI runs the full suite on every pushed commit. When a CI job fails, reproduce that job, or its failing test, on Boat with the script and fix it.
- A plain or `--full` run is for reproducing a CI failure, for heavy checks that must not run on the Pi or the Mac (see the Node `assert` gotcha below), or for checks CI doesn't run.
- CI doesn't run these, so they stay required before hand-off when the change calls for them:
  - **Baseline comparison.** After a change to physics, traffic, planner or router, the seeded benchmark compared with the newest committed run in `data/runs/` (`/bench` above). `Benchmark passed` only fails a failed route on Kitsilano, seed 1, `bare` and `city` in dry weather (`bench_node.mjs --check 1`); it compares nothing with the committed run, and its fog, rain and snow legs run weekly. Run it under Node on Boat with `-- CMD` (server and `scripts/bench_node.mjs` in one command) and copy the run back.
  - **Feature registry moves.** The before-and-after comparison of the bare and city suites, every challenge and both road tests (Registered features, below).
  - **WebKit.** WebKit `/bench` runs and `scripts/shot.swift` screenshots, on the Mac.
  - **Live Jev verification.** `scripts/verify_jev.py` without `--offline` after wording changes, only when the owner asks (paid; see Boat).
- The hand-off report names the targeted checks that ran (and any of the checks above) and says that CI runs the full check.

Use `discover -s tests` for Python tests. It makes the tests' top-level `helpers` import work. `tests/helpers.py` then puts the project root on `sys.path`.

Browser-side checks need the server running:
- `/tests`: browser unit tests (car model, controller, collisions, candidates, state). Use `/tests`, not `/tests/run.html`: only routes in `server.py`'s `PAGES` get the session token. API POSTs without it return 403.
- `/bench`: closed-loop benchmark. Lockstep plus the Rules brain is deterministic, so rerun suite seed 1 and compare with the newest committed run in `data/runs/` from the same JavaScript engine with the same map, suite size, preset and weather (`docs/rules-baseline.md` lists them) after any change to physics, traffic, planner, or router.

Headless (macOS): `swift scripts/shot.swift URL OUT.png [wait] [post_js] [pre_js] [settle] [timeout]` screenshots a page in an offscreen WKWebView and runs JS. The page is usually `visibilityState: hidden`, so `requestAnimationFrame` never fires. Step the app with `window.__jev.advance(seconds)`, and run the benchmark with `await window.__bench.run({ brain, count, seed, save })`. The default timeout is `settle + wait + 30` s, so pass the 7th argument for long runs. `SHOT_SIZE=390x844` sets the viewport (default 1440×900); `?touch=1` shows the touch controls on a desktop. In a restricted agent sandbox (not Boat), `uv` (which writes to `~/.cache/uv`) and the server (which binds a port) fail, so run them in Boat.

Docs: [`docs/reference/`](docs/reference/README.md) has one page per topic and feature; [adding a challenge](docs/adding-a-challenge.md); [adding a driver](docs/agents.md).

## Cloud sandboxes (Boat)

Use Boat as the compute for your task (owner, 2026-11-25). Anything that runs a program to do work happens in a Boat sandbox, never on the machine the agent runs on: builds, tests, lint, benchmarks, fixture builds, large downloads, Docker, untrusted code and long jobs. That machine is the owner's Mac or a Raspberry Pi with 8 GB of RAM shared by every agent and the T3 server, where one heavy command stalls them all. Only light work stays local: reading and editing files, git, searches such as `git grep`, the `boat` CLI and the exceptions this file lists. If you're unsure, use Boat. If Boat can't start a sandbox, don't fall back to local compute: tell the owner what still needs a Boat run. Work this file keeps on the Mac (no GPU or macOS on Boat) can't run on the Pi either; an agent there leaves it to the owner and says so in its hand-off.
Docs: https://docs.boat.dev/llms.txt. Prices and limits: run `boat limits`; never quote prices from memory.

The account, shared by all the owner's projects, allows 840 sandbox starts a day; each create or resume uses one. Run `boat limits` before Boat work. With no starts left, finish the work, then tell the owner what still needs a Boat run; don't wait or retry.

- Checks: `scripts/boat-check.sh` runs lint, the Python tests, the offline Jev requests and the fixture check; `--full` adds every `scripts/test_*.mjs`, in parallel with CI's limit (`scripts/node_checks.mjs`); `-- CMD` runs any command in the checkout. Run the checks this way, not with `boat run` ([Boat checks](docs/reference/development.md#boat-checks)). While working, run targeted checks with `-- CMD` and leave the full suite to CI ([Checking work](#checking-work)).
- One sandbox per worktree: the first check creates it from the warm snapshot `jev-fsd-warm` (Node 22, uv, Python, Biome and a clone with its dependencies), later checks reuse it, and it stops as soon as each check ends. `--full` runs on `xlarge`, the plain check and `-- CMD` on `default`. `JEV_BOAT_TYPE`, `JEV_BOAT_JOBS` and `JEV_BOAT_IDLE` override the size, the parallel checks and the idle time (default 0). How the script syncs the tree, resumes and keeps auto-stop ahead: [Boat checks](docs/reference/development.md#boat-checks).
- Never share a sandbox between agents: agents in one worktree each set their own `JEV_BOAT_SLOT`. When the agent's work ends, run `scripts/boat-check.sh --done` (deletes it); `--stop` keeps it for later.
- After a toolchain or dependency change (Node, `uv.lock`, `package-lock.json`) reaches the default branch, refresh the snapshot with `scripts/boat-check.sh --save`. It builds the snapshot from that branch in a fresh sandbox that runs no worktree code (one start).
- Each check resets the checkout, removing untracked and ignored files (`data/runs/` included): copy results you want to keep back to this Mac first (`boat scp -r "$id":jev_fsd/data/runs ./data/`; `--status` shows the id). Saved snapshots and other gitignored files are never pushed, so copy in any a `verify_jev.py` run needs.
- Genuine one-offs only (not checks of this worktree): `boat run --push . -- CMD` (new sandbox, run, cost, delete; exits with the command's exit code). Other generic commands: `id=$(boat new --name jev-fsd-city-replay --json | jq -r 'select(.event=="ready") | .id')`, `boat exec "$id" --cwd my-app "npm test"` (30 s timeout; `--timeout 0` = no limit), `boat exec "$id" --detach "npm run dev"` then `boat exec "$id" --status <pid>`, `boat push "$id" ./my-app`, and `boat stop "$id"` or `boat delete "$id" --yes` when done.
- Always pass the sandbox id. `current` does not work in a non-interactive shell.
- Name every sandbox you create by hand (`boat new`, `boat run --keep`) with `--name jev-fsd-<purpose>` (for example `--name jev-fsd-city-replay`); never leave Boat's default "Box <date>" name. The script names its own `jev-fsd-check-…` and `jev-fsd-warm-build`.
- Stay on this Mac: `scripts/shot.swift` (WKWebView), WebKit/Safari benchmark runs and the WebKit baselines in `docs/rules-baseline.md`. For WebKit runs against a server in Boat, `boat forward` it to the same port on this Mac, because the server checks the port in `Host` and `Origin`.
- `server.py` binds 127.0.0.1, accepts only loopback Host names (`jev/security.py`) and holds paid API keys. Never expose it with `boat host` or the in-sandbox `host`. To see it, use the sandbox's desktop Chrome or `boat forward` the port to this Mac.
- Use Node 22 in Boat, as CI does. `boat push` leaves out `.git` and gitignored files (`data/runs/`, `data/snapshots/`); `tests/test_results.py` needs git, which is why checks run in the clone.
- Check sandboxes carry no credentials: the script creates them with `--no-env` (no GitHub token, agent logins or API keys), so an offline run can't spend credits, and with `--fail-fast`, so a start that finds no ready machine isn't counted and is retried briefly.
- Live, paid runs (recordings, arena or benchmark runs that call a model, `scripts/verify_jev.py` without `--offline`) happen only when the owner asks. Each gets its own sandbox from the Boat environment `jev-fsd-live`, which injects only `TYPESAFE_API_KEY` and `ANTHROPIC_API_KEY`: `id=$(boat new --environment jev-fsd-live --name jev-fsd-live-city-pilot --json | jq -r 'select(.event=="ready") | .id')`, and `boat delete "$id" --yes` afterwards. Never use the check sandbox for one. Don't read key values from `.env` or pass them on the command line, never copy `.env` into a sandbox, and keep to the budget rules below.

## Architecture

**Split of responsibilities.** Python (`server.py`, `jev/`) builds the map pack from OpenStreetMap, plans routes, and handles live calls to Jev, configured decision models and LLMs. Stored provider keys stay on the server. The browser runs physics, traffic, sensing, manoeuvre planning and rendering under `static/js/`. Node benchmarks use the same simulation. The server is loopback-only with CSRF defences (`jev/security.py`); state-changing requests need the `X-Jev-Token` header that `common.js` sends.

**Map pack pipeline** (`jev/osm/`): fetch → parse → project to meters → road graph (directed edges, two-way lanes right of the centerline, one-way lanes centred around it, parking lanes widen `asphalt`, roundabout rings pushed out to a drivable radius) → controls (signal and junction stop lines set back for the crosswalk, mid-block stops at the mapped sign, roundabout yield lines outside the ring) → buildings → `data/maps/<key>.v<PACK_VERSION>.pack.json`. Packs are cached and committed. If the pipeline output changes: bump `PACK_VERSION` in `jev/osm/pack.py` and the version assertion in `tests/test_osm.py`; replace the old packs for every bundled map, including Kitsilano. Update tests and scripts that load a versioned filename. Restart the server to clear its in-memory cache.

**Layers beside a pack** (`<key>.<layer>.v1.json`) come from the raw OSM download (`scripts/fetch_map.py` rebuilds scrambles with `--calming` and turn restrictions with `--restrictions`), leave the pack as it was and are committed: transit, crossings, zones, rail, calming, scrambles, buslanes, restrictions, contraflow, driveways, parks, bridges. Load crossings `v2` when present (Toronto and Ottawa have Ontario pedestrian crossovers), falling back to `v1`; never bump the street pack for a crossing-layer change. `server.py`, `scripts/build_demo.py` and any Node test that loads a pack for the challenges must load every layer.

**One decision cycle** (`static/js/brain/brain.js`, `Autopilot`): `sensors.buildSnapshot` → `candidates.sampleCandidates` → `simulateAll` (3 s forward sims) → `state.toJevState` + `buildQuestions` → brain → `apply`. The only difference between the Jev and Rules brains is the "brain" step: `rules.js` scores the surviving candidates; `jev.js` posts to `/api/decide`. A timeout, request error or invalid vector falls back to Rules and increments `world.violations.fallbacks`. A model choice that leaves a route or headlight question to its default counts as partial.

**Invariants that span files:**
- **Parking reservations have one shape.** Write `slot.reserved = { owner, sFrom, sTo }` only with `reserveSlot` (`sim/parking.js`); the span is along the slot's own edge. Test `reserved?.owner` when releasing. Never infer a span from the owner's spec (driveway owners are map records). Check `scripts/test_parking_reservations.mjs`.
- **A thrown simulation step fails its drive.** The app pauses with a persistent error and restart control while frames keep rendering. Benchmark and arena results add `simulation_error` only on failure; `failures()` and saved evaluation validation keep that verdict; successful result shapes are unchanged. Checks: `scripts/test_simulation_errors.mjs` and the browser recovery case.
- **One road vehicle model.** The ego car, road traffic, cyclists and candidate predictions use `sim/vehicle.js`. It models actuator lag, jerk limits, ABS and stability control. Vehicles with mass use the dynamic bicycle model with Fiala tires and weight transfer at speeds of 3 m/s and above. Below that speed, and for the massless `BIKE` spec, the model is kinematic. The autopilot and its predictions execute manoeuvres with `controller.applyLaw`. NPCs supply their own controls. Trains follow their track in `sim/rail.js`. A physics change changes predictions, candidate eligibility and test geometry together. Size-dependent code reads `vehicle.spec`, not `CAR`.
- **Grip.** Each World calls `setWeather` in `sim/weather.js` to set the global `ROAD.mu`. Use `comfort()` in `sim/vehicle.js` for grip-based cornering and braking targets. Black ice alone varies grip by location through `ROAD.gripAt`. Each World resets that hook. With ice off, branch on the null hook and preserve vehicle stepping bit for bit. Do not multiply by 1. Keep `comfort()` global and leave `hard_brake` and the shared emergency brake at full strength.
- **`Route.project(x, y)` without a hint tracks the ego and updates `route.hint`; with a hint it must not.** Projecting other vehicles or forward sims without a hint corrupts the ego's route position.
- **Obstacles.** `world.obstaclesNear(x, y, r)` returns traffic, parked cars and their open doors (`sim/parking.js`, spatial grid), pedestrians (`sim/pedestrians.js`) and the feature actors kept out of `world.npcs` (contraflow cyclists, driveway reversers, geese, barricades). Use it for collisions with road users and roadside objects. Buildings and solid scenery have a separate index, `world.staticObstacles`.
- **Lane laws treat `vTarget` as a ceiling.** `applyLaw` and `sensors.desiredSpeed` both use `curveProfileSpeed` in `sim/controller.js`. Sensing stores the target in `snap.target`. Jev sees its speed as `car.target_speed` in `brain/state.js`.
- **One step function.** The app loop (`main.js`), benchmark runner (`bench/runner.js`) and arena (`lab/evaluation.js`) all call `stepWorld` in `sim/step.js`. The autopilot's `now` is sim time in ms (`world.t * 1000`), never wall time, so replays are exact.
- **Routing parity.** The Python router (`SHARP_TURN_DEG` in `jev/routing.py`), NPC path selection (`SHARP_TURN` in `sim/npc.js`) and `browserRoute` in `demo/routing.js` use a 130° sharp-turn threshold. This is separate from the 150° U-turn classification. The router rounds the real corner (`_round_corner` / `_blend` in `jev/routing.py`); `joinLanes` in `static/js/map/mapdata.js` mirrors it for NPC paths. Keep them in sync; naive end-to-start joins make right turns back up. `tests/test_parity.py` checks turn decisions and lane joins on `tests/fixtures/parity_cases.json`. A case marked `known_difference` must keep disagreeing, so remove the mark when you bring the two into line.
- **Road surface for driving.** The candidates' off-road rejection and the off-road audit use `surfaceDistance` (`map/junctions.js`): `roadDistance` plus the junction fills the renderer draws, from the one `junctionFills`. Scenery placement keeps `roadDistance`. No parking bay goes where its car would reach more than 0.3 m into the travel lane (`bayIntrusion`, `sim/parking.js`), and no parked car whose jittered body would (`footprintIntrusion`; the bay stays, empty); a left-out bay or car still draws its randoms and uses its car number.
- **Street cross-section.** `map/streets.js` (gutter, curb, boulevard, sidewalk) is shared by the renderer and the pedestrians; crosswalk positions depend on it and on the asphalt width (which includes parking lanes).
- **Emergency vehicles and the car's pull-over** (`sim/emergency.js` and the record `sim/features/emergency.js`: `emergencyYield` in `sim/emergency-yield.js`, `EmergencyTraffic.step` in `sim/emergency-traffic.js`, the audit in `sim/emergency-audit.js`).
  - When sensing calls for yielding, `max_speed_mps` caps every lane candidate. Driving on ahead of the siren is exempt. A short pull-over finishes its sideways move within its stopping room in both prediction and execution (`steerAtStop` in `applyLaw`). Set the plan's `steer_at_stop` when it starts short or has yet to begin after one second with less than half its steering distance left. A queue that shortens the stop also activates `steerAtStop` on the candidate.
  - `emergencyLead` latches drive-on authorisation in `world.evCalls` (the record's calls map). Sensing and every emergency audit branch read that latch. A pull-over, a physically blocking queue or a control-line stop recorded when the siren arrived can qualify. The line stop may be between a give-way or stop line and `sPeek`. A later stop cannot create that exception. Turning cannot turn an authorised lead into a new crossing call. Even with authorisation, hold still while the emergency vehicle is alongside.
  - `EmergencyTraffic.yieldStop` (through traffic's `trafficStopAt` hook) is a physical front-bumper target. Add back the IDM standstill gap with the following policy on or off, so traffic clearing a junction or narrowing gets its planned rear clearance. Traffic waiting for a snowbank narrowing stays in its approach lane, outside the shared corridor.
  - The ego car stops outside the `EV_BOX_M` junction box. The audit measures its rear axle and allows lateral settling room, including when snowbanks move its target left. Beside parked cars on a narrow lane, pull over as far as `parkedRoom` allows and use the same settling allowance in the audit. A car stopped with a vehicle alongside on its right or at a reversing parker's hold line (`heldInQueue` in `sim/emergency-audit.js`, through the feature's `evQueueHold` hook) is yielding. Once released from a queue it has `AUDIT_EV_PULL_S` to pull over.
  - When the siren switches off, the emergency vehicle resumes ordinary traffic control. Keep its passing line until `sweptBodyGap` shows room to merge back.
- **Registered features.** `static/js/sim/features/index.js` registers every opt-in feature: transit buses, school buses, streetcars, trains at level crossings, emergency vehicles, destination parking, hidden hazards, driveway reversers, ball chase, potholes, geese, black ice, snowbanks, puddles, traffic parking, road closures, police officers, tailgaters, double-parked vans, contraflow cyclists, sun glare, garbage trucks, traffic calming, red-light runners, crossing guards, Ontario pedestrian crossovers, roadside stops, following distance, turn restrictions, high beams, no-turn-on-red signs, scramble crossings, work zones with flaggers, power cuts, overnight flashing, left on red, amber lights, bus lanes, snow plows, lane closures and passing cyclists. Each feature has one record for its option, World or fleet state, optional seen flag, audit calls and hooks, and one entry in `FEATURES`. The core runs hooks at named slots (`SLOTS`) to preserve the order of candidates, rejections, wording, prompt lines, events and failures. Never name a registered feature in the core files; add a hook or slot instead and check `scripts/test_feature_registry.mjs`. Nor in `main.js`, the browser adapter `render/feature-views.js` or a shared renderer (`render/cars.js`, `people.js`, `roads.js`, `minimap.js` and the rest that no record's `view` imports): a record says where its render module is (`view: () => import("../../render/<its module>.js")`), and that module's `view` export declares its scenery, scene objects, vehicle kinds, parked meshes, per-frame effects and what people carry, each with an `order` that keeps scenes as they were drawn; HUD notices, event badges and sounds are record fields. `scripts/test_feature_exit.mjs` checks both, with a throwaway feature registered in the test. After changing the adapter, a view or a shared renderer, compare scene graphs before and after with `scripts/render_parity.mjs` ([running the render comparison](docs/feature-interface.md#running-the-render-comparison)); CI does not run it. When moving a feature onto the registry, compare the bare and city suites, every challenge and both road tests before and after. Include city weather that exercises the feature. Compare every field except timings. See the [feature interface](docs/feature-interface.md).
- **Manual input is analog.** `World.stepManual` takes `throttle`, `brake`, `left` and `right` as booleans or amounts from 0 to 1; `true` must drive exactly as 1 and `false` as 0 (`scripts/test_gamepad_touch.mjs`). The keyboard, the gamepad (`ui/gamepad.js`) and the touch controls (`ui/touch.js`) combine in `ui/input.js` (`addSource`, `poll` once a frame in `main.js`); new inputs are added as sources, never inside the simulation.
- **Coordinates.** Sim is x east, y north, meters; headings are radians counter-clockwise from +x; `lateral > 0` means right of travel (the right normal is `(sin h, -cos h)`). Three.js is `(x, z, -y)`. In meshes placed with `rotation.y = heading`, local +x is forward and local +z is the right side.
- **Ground rendering order.** Coplanar ground layers (grass, sidewalk, curb, asphalt, markings) use `LAYER` and `groundLayer()` in `render/scene.js`. Draw the sky first. Depth-test every ground layer in fixed `renderOrder`. Only the grass base writes depth. The other layers use polygon offset. Keep the roundabout's `islandCurb` and `island` layers above asphalt. Speed humps and the like rise above the ground, are depth-tested and drawn after the markings (`render/traffic-calming.js`). Anything placed below y = 0 breaks this. Overlays are transparent and depth-tested so cars hide them.

**Jev prompting.** Jev takes question wording literally; criteria must say *when* an option is correct. `buildQuestions` asks `motion` when `needsMotionQuestion` holds and `vector` when at least two candidates are eligible. Unasked motion defaults to drive. A sole eligible candidate answers the vector question locally. It also asks `headlights` when the snapshot includes headlights and `route` when there are multiple route options. After changing sensing, candidates or Jev wording (including a feature record), run `node --experimental-default-type=module scripts/build_jev_fixtures.mjs --check` and regenerate intended fixture changes. After wording changes, run `scripts/verify_jev.py --offline`; the live, paid run happens only when the owner asks ([development](docs/reference/development.md)). Keep Jev question instructions under 4,000 characters on the city suite. The server refuses instructions over 6,000 characters (`jev/decide.py`). Keep a Jev decision under 5,500 input tokens and the LLM system prompt under 6,000 tokens (`docs/model-results.md`).

**Benchmark** (`static/js/bench/`; [internals](docs/reference/benchmarks.md#benchmark-internals)): pass/fail lives in `failures()`. `decidedBy` fields are reported for every driver but Rules. `features` is `bare` (default, every opt-in feature off) or `city` (`freeDriveOptions` without destination parking, 15:30 Monday, routes keeping to turn restrictions). Keep the default weather and the defaults for `--park`, `--hour`, `--without` and `--cover` compatible with saved runs. Allow the greater of 120 seconds and route length at 2.5 m/s. In city snow divide that limit by `WEATHER.snow.speed`. Only a road-closure re-plan that replaces the route can extend the deadline, using distance already driven plus the new route length. Model recordings (`brain/recording.js`, lockstep only) are committed under `data/recordings/`; with no tape every result is as before.

- **Two tracks.** `guarded` (the default when a record omits the track) and `open` (`brain/tracks.js`): on the open track the filter flags road-rule failures instead of removing them, and only a predicted collision is still removed. Rules and the built-in agents keep to the unflagged manoeuvres, so their open-track drives must match their guarded ones in every field but `track`, `flagged_choices`, `flagged_by_check` and the trace's offered candidates (`scripts/test_open_track.mjs`). Guarded results and configs omit track-specific fields.
- **Scores are display-only.** `bench/scores.js` reads saved fields and is never written into results. A formula change bumps `SCORES_VERSION` and updates `docs/rules-baseline.md`.
- **Held-out routes.** Never debug, replay or tune against a held-out route (`bench/heldout.js`, seeds in `HELDOUT_SEEDS`). Record a failure there, reproduce it on a fresh tuned seed and fix it there. Report held-out results apart.
- **Suite versions.** The numbered definitions in `data/suites/` are frozen. Bump the version when a change alters any result under the canonical conditions. Keep the previous definition and publish comparisons within one version. Versioned reports, manifests and tapes must agree. A partial run can qualify only after a merge verifies the complete set. Older unlabeled artifacts stay legacy. See [suite versions](docs/reference/benchmarks.md#suite-versions).
- **Published results are generated.** `data/results.json` and the README block between `<!-- results:start -->` and `<!-- results:end -->` are built by `uv run scripts/build_results.py` from `data/results/<date>/*.json`, `data/recordings/*.json.gz`, curated `data/submissions/<date>/*.json` with their matching tapes, and the newest tracked standard run in `data/runs/` per driver, map, preset, weather, suite size and seed. Held-out, parking, hour, feature-subset, covering-row and explicit-track variants are excluded from standard run rows. Never edit the JSON or README block by hand. Rerun the script after committing a run, a recording or a published result. Add each new map to `jev.maps.MAP_CATALOG`, the source for `MAP_NAMES`. `tests/test_results.py` checks the generated outputs and map names. The leaderboard (`static/results.html`, `ui/results.js`, `lab/results.js`) reads the same file through `/api/results`, or `demo-data/results.json` in the demo. Follow [the submission workflow](docs/agents.md#publish-a-verified-submission) for outside drivers.

**Challenges** (`lab/challenges/<id>.js`, registry `lab/challenges.js`): one module per challenge, named by its id, exporting `challenge` (the definition) and `scenario(map, challenge)`, and optionally `install(world, fleet, challenge, scenario, at)` (after `installBase` has set `world.challenge`) and `step(world, fleet)` (default `stepAuthored`: `release` once `trigger` holds near `world.challenge.at`). Shared parts live in `lab/challenges/shared/` (`kit.js`: `laneScenario`, `installBase`, `stepAuthored`, oncoming/all-way/through traffic). For a new scenario, apply the [roadmap admission rule](ROADMAP.md#admission-rule-for-new-scenarios). To add a challenge, write its module, import it in `lab/challenges.js` and put it in `MODULES` in lab order; `scripts/test_challenge_modules.mjs` checks the layout. The registry finds a module by id, then by hazard when a test changes it, so keep hazards distinct unless two lessons share code.

**Challenges, practice, debriefs and road tests** (full rules: [adding a challenge](docs/adding-a-challenge.md#rules-for-practice-debriefs-and-road-tests)). Every verdict (practice progress, debriefs, road test sheets) comes from `challengeFailures` (`lab/practice.js`) and so `failures()`, with parking where required, independently of the coaching grade. Only the original unchanged manual attempt counts as practice. `ROAD_TESTS` stay out of `CHALLENGES`; `RoadTestObserver` is attached to road test drives alone and only adds incidents, so other reports stay field-for-field identical. Incident replay never seeks a different recording.

### Opt-in features

Read the linked reference before changing a feature, including its “Agent rules” section where present.

- **Opt-in.** Free drives enable the World and fleet options below unless `?<flag>=0`. Placement also depends on the map and conditions. Snowbanks form only when the drive starts in snow. School buses run from 07:00 to before 17:00. Challenges set options or place actors explicitly. `freeDriveOptions` (`sim/free-drive.js`) enables registered World and fleet options using the lowercase form of each key as the query flag. Define other free-drive options there. `scripts/test_free_drive.mjs` checks that the application and city benchmark use these options, including each registered feature's disable flag.
- **Off means untouched.** A disabled feature may initialise empty state. Skip its placement and simulation work. New features must draw no random numbers while off. Preserve seeded results and report shapes. An enabled feature uses its own random stream. The fleet initialises its first emergency dispatch time from its private siren stream even when dispatch is off.
- **One shared test** decides the situation for sensing, candidates (law and rejection), Rules, the cautious agent, the model wording, traffic and cyclists, the coach and the audit. Never re-derive it in one of them.
- **Gate feature-specific metrics.** Add a feature's metric to the report and apply its failure threshold only after its World seen flag is set. Passing cyclists uses the option itself. Shared counters such as `stop_signs` and `failed_to_yield` are always reported.
- **Render-only parts stay render-only** (lamps, flashes, spray, flinches, jolts).

Where features reach into shared code:
- **Signals.** `sim/signals.js` owns `setScrambles`. Its `planOf` picks `scramblePlan` only while scrambles are on. `sim/night-flash.js` owns `setNightFlash`, called by each World and on replay restore. Flashing suppresses advance greens, scrambles and right-on-red; outages take precedence.
- **The clock.** Time-dependent features read `world.clock` (`hour`; `weekday`, Monday = 0 the default; `day`, `utc_offset` only when present; free drives' clock has no `day`). Without a clock no bus lane is in effect and no signal flashes.
- **Routing.** Red-turn bans never feed ordinary routing restrictions. An empty or missing `avoid` (road closures) must leave every route exactly as before; lockstep evaluation awaits `autopilot.detourRouting`. The server breaks equally near lane snaps by edge ID, then lane index, independently of Python's hash seed. Left-on-red city bounds fail closed; extend them only after checking provincial law.
- **Parking.** Every parking branch leaves the `parkAtGoal` false path exactly as it was; `planSpace`'s `anywhere` only skips the destination checks; traffic keeps back from a car parking ahead through `World.parkHold`, which the destination-parking record's `trafficKeepBack` hook reads.
- The driven car has no `id`; lane closures and officers call it `EGO_ID` ("ego"). Without `passCyclists`, candidates keep the 1 m `passes_cyclist_too_close` rejection. Compact trace folding must compare beam choices.

## Gotchas

- NPC colors and car body styles are render-only. Preserve them when moving a car between traffic and parking. Driving decisions must ignore them.
- In Node tests, never pass sim objects (World, Route, MapData, vehicles) to `assert`; assert on primitives such as ids, counts and booleans. A failing assert on one makes Node print the whole object graph, which has used 70–200 GB of memory on a 16 GB Mac, and `--max-old-space-size` does not stop it. Run heavy checks in Boat, never on the Pi or the Mac: `scripts/boat-check.sh -- CMD` for one file, and when the whole set has to run outside CI, `scripts/boat-check.sh --full` runs them in parallel on a 32 GB `xlarge` sandbox (at least 23 GB stayed free) and fails a file the kernel kills for memory. The full Playwright suites run in CI.
- `scripts/build_demo.py` checks the target of every `import("…")` it finds in a JavaScript file, comments included: a made-up path in a comment (`import("../render/<feature>.js")`) fails the demo build.
- End Node tests that build an `Autopilot` with `process.exit(0)` after the assertions. Tests importing `bench/runner.js`, even through arena evaluation, keep Node alive through its module-level `MessageChannel`. Run `scripts/test_*.mjs` with Node 22, as CI does; Node 24 rejects `--experimental-default-type`.
- CI (`.github/workflows/demo.yml`) runs `scripts/test_*.mjs` in six shards `scripts/ci_shard.mjs` plans from `scripts/ci_test_times.json`, and stops any that runs longer than `NODE_TEST_TIMEOUT` (360 s). Add a new check's measured seconds to the times file (unlisted files count as the median), and change the shard count in both the matrix and the `--shards` argument; `scripts/test_ci_shard.mjs` checks they match. Split a check rather than raise the limit far.
- `window.__bench.run` saves by default. The local server writes to gitignored `data/runs/` (baselines need `git add -f`). The static demo uses localStorage. Pass `save: false` for a comparison run. For before/after benchmarks, see [before-and-after runs](docs/reference/benchmarks.md#before-and-after-runs).
- Saved arena runs are kept in IndexedDB (`openEvaluationHistory` in `static/js/lab/history.js`): the newest `MAX_SAVED_RUNS` (20) within `MAX_SAVED_BYTES` (200 MiB), with the oldest evicted first and the selected baseline kept until last. A `QuotaExceededError` can force more evictions. The 9 MiB `MAX_HISTORY_BYTES` cap applies only to the localStorage fallback (no IndexedDB: some private windows, blocked storage, Node), which keeps 10 runs; the history store is async, checked by `scripts/test_arena_storage.mjs` with a fake IndexedDB. CI enforces the arena storage cap: `scripts/test_drive_lab.mjs` measures two full challenge runs with Rules and the cautious agent against the fallback cap and fails over it ([per-challenge figures](docs/adding-a-challenge.md#arena-storage)).
- The committed model recording `data/recordings/stub-llm-kitsilano-s1.json` (a stub model, not a real one) replays a whole drive, so a change to physics, traffic, sensing, candidates, the decision state, the LLM prompt or a drive result's fields makes `scripts/test_model_recording.mjs` fail. If the change is intended, rewrite it with that script's `--write`. Model recordings replay exactly only on the JavaScript engine they were made on (see "Record a model run" in `docs/agents.md`).
- Live model runs: parallel runs against one server share `JEV_FSD_RPM` unless an endpoint sets its own `rpm`. Calls over the applicable cap get a local 429 and fall back to Rules. Give each run its own server or adjust the applicable limit. Check the provider's own bill during a run, and ask before spending past the agreed budget.
- `tests/test_doc_links.py` checks every relative link and anchor in `README.md`, `AGENTS.md`, `ROADMAP.md` and `docs/`; run it after moving or renaming a heading.

## Decisions

- Ask before adding any dependency, tool or service.
- Live model test runs (recordings, published results, the arena and benchmark runs that call a model) use Jev and Claude Haiku 5.5 (`claude-haiku-5-5`, through the Claude Platform, `ANTHROPIC_API_KEY`) only. Don't use Claude Sonnet.
- New maps are Canadian cities. LLM drivers use a generic OpenAI-compatible endpoint, or Anthropic's Messages API for Claude models (`"api": "anthropic"`, the Claude Platform preset in `jev/llm_setup.py`).
- Hosted provider presets in Connect a model are the major labs' own APIs (OpenAI, Anthropic, Google, xAI, Mistral), through an OpenAI-compatible endpoint where the lab offers one, plus OpenRouter and Groq. Don't add presets for Chinese-hosted APIs.
- Boat checks reuse one sandbox per agent or worktree through `scripts/boat-check.sh`; `boat run` is for genuine one-offs, since every project shares the account's daily starts (owner, 2026-11-21).
- Boat sandboxes are named `jev-fsd-<purpose>`, since `jev-` alone could be jev_fsd or jev_lab (owner, 2026-11-21).
- Live, paid runs use their own sandbox from the Boat environment `jev-fsd-live`, created when the owner asks and deleted afterwards; check sandboxes carry no credentials (owner, 2026-11-21).
- Boat check sizes: `--full` on `xlarge` with one Node check per vCPU, everything else on `default` (owner, 2026-11-21; [measured](docs/reference/development.md#sizes-and-parallel-checks)).
- Boat checks never idle: every size stops as soon as its check ends (owner, 2026-11-22; [measured](docs/reference/development.md#boat-checks)).
- CI is the full check (owner, 2026-11-22): CI runs the full suite once, on the pushed commit, and agents don't run it (`scripts/boat-check.sh` or `--full`) before handing work back. While working they run targeted checks on Boat with `scripts/boat-check.sh -- CMD` (the tests that cover the change and lint for the areas touched); CI runs the full suite on every pushed commit, and a failed CI job is reproduced on Boat with the script and fixed. A plain or `--full` run is for reproducing CI failures, heavy checks that must not run on the Pi or the Mac, and checks CI doesn't run. The checks CI doesn't run stay required before hand-off, and the hand-off report names the targeted checks that ran and says CI is the full check ([Checking work](#checking-work)).
