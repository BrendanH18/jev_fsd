# Agent instructions

## Commands

No build step and no linter are configured. Python runs through `uv` (one dependency, `typesafe-sdk`); the browser app is plain ES modules with Three.js from a CDN import map.

```sh
uv run server.py                                            # serves http://127.0.0.1:8322 (PORT to change)
uv run python -m unittest discover -s tests                 # offline Python tests
uv run python -m unittest discover -s tests -p "test_routing.py"          # one file
uv run python -m unittest discover -s tests -k test_route_never_backs_up  # one test
uv run scripts/fetch_map.py [bbox|preset] [--force]         # build/rebuild a map pack
uv run scripts/verify_jev.py                                # live: data/snapshots/*.json against the real model (costs credits)
```

`python -m unittest tests.test_x` fails: `tests/helpers.py` fixes `sys.path`, so always use `discover -s tests`.

Browser-side checks need the server running:
- `/tests`: browser unit tests (car model, controller, collisions, candidates, state). Use `/tests`, not `/tests/run.html`: only pages listed in `PAGES` in `server.py` get the session token injected, and every API call without it gets a 403.
- `/bench`: closed-loop benchmark. Lockstep plus the Rules brain is deterministic, so rerun suite seed 1 and compare with the newest committed baseline in `data/runs/` after any change to physics, traffic, planner, or router.

Headless (macOS): `swift scripts/shot.swift URL OUT.png [wait] [post_js] [pre_js] [settle] [timeout]` screenshots a page in an offscreen WKWebView and runs JS. The page is usually `visibilityState: hidden`, so `requestAnimationFrame` never fires. Step the app with `window.__jev.advance(seconds)`, and run the benchmark with `await window.__bench.run({ brain, count, seed, save })`. The default timeout is `settle + wait + 30` s, so pass the 7th argument for long runs. `uv` and the server need to run outside a sandbox: uv writes to `~/.cache/uv` and the server binds a port.

## Architecture

**Split of responsibilities.** Python (`server.py`, `jev/`) builds the map pack from OpenStreetMap, plans routes, and proxies decisions to TypeSafe (the API key never reaches the browser). Everything that moves (physics, traffic, sensing, planning, rendering) runs in the browser under `static/js/`. The server is loopback-only with CSRF defences (`jev/security.py`); state-changing requests need the `X-Jev-Token` header that `common.js` sends.

**Map pack pipeline** (`jev/osm/`): fetch → parse → project to meters → road graph (directed edges, lanes offset right of the centerline, parking lanes widen `asphalt`, roundabout rings pushed out to a drivable radius) → controls (signals, stops, roundabout yields; `s_line` set back behind the crosswalk) → buildings → `data/maps/<key>.v<PACK_VERSION>.pack.json`. Packs are cached and committed. If the pipeline output changes:
- bump `PACK_VERSION` in `jev/osm/pack.py` and the version assertion in `tests/test_osm.py`;
- rebuild the Kitsilano pack and replace the old pack file with it;
- restart the server, which caches packs in memory.

Layers beside a pack (`<key>.<layer>.v1.json`: transit, crossings, zones, rail, calming, scrambles, buslanes, restrictions, contraflow (the one-way streets cyclists may ride both ways), driveways (where mapped driveways meet the streets); crossings is `v2`, with Ontario's pedestrian crossovers, for Toronto and Ottawa, and loaders prefer it to `v1`) come from the raw OSM download (`scripts/fetch_map.py ... --transit`, `--zones`, `--rail`, `--calming`, `--crossings`, `--buslanes`, `--restrictions`, `--contraflow` or `--driveways`), leave the pack as it was, and are committed too. `server.py`, `scripts/build_demo.py` and any Node test that loads a pack for the challenges must load every layer.

**One decision cycle** (`static/js/brain/brain.js`, `Autopilot`): `sensors.buildSnapshot` → `candidates.sampleCandidates` → `simulateAll` (3 s forward sims) → `state.toJevState` + `buildQuestions` → brain → `apply`. The only difference between the Jev and Rules brains is the "brain" step: `rules.js` scores the surviving candidates; `jev.js` posts to `/api/decide`. Timeouts and invalid answers fall back to Rules and increment `world.violations.fallbacks`.

**Invariants that span files:**
- **One car model everywhere.** `sim/vehicle.js` (dynamic bicycle with Fiala tires and weight transfer above 3 m/s, kinematic below; actuator lag and jerk limit; ABS/stability control; grip `ROAD.mu`) and `controller.applyLaw` drive the ego car, every NPC, every cyclist (`BIKE` spec, no mass, so always kinematic), and every candidate forward sim. A physics change changes predictions, candidate eligibility, and test geometry together. Size-dependent code must read `vehicle.spec`, not `CAR`.
- **Grip is global.** `ROAD.mu` is module state set by `setWeather` (`sim/weather.js`), which `new World()` calls. `comfort()` in `vehicle.js` derives cornering/braking targets from it; never hard-code 2.5 m/s^2 style constants again.
- **`Route.project(x, y)` without a hint tracks the ego and updates `route.hint`; with a hint it must not.** Projecting other vehicles or forward sims without a hint corrupts the ego's route position.
- **Obstacles.** `world.obstaclesNear(x, y, r)` returns traffic, parked cars (`sim/parking.js`, spatial grid) and pedestrians (`sim/pedestrians.js`). Use it rather than `world.npcs` for anything that can be hit.
- **Lane laws treat `vTarget` as a ceiling.** `applyLaw` caps it with `curveProfileSpeed` (in `controller.js`, also used for `target_speed` in `sensors.js`).
- **One step function.** `sim/step.js` `stepWorld` is used by both the app loop (`main.js`) and the benchmark runner (`bench/runner.js`). The autopilot's `now` is sim time in ms (`world.t * 1000`), not wall time, and must stay that way for replays to be exact.
- **Two copies of the sharp-turn rule.** `SHARP_TURN_DEG` in `jev/routing.py` and `SHARP_TURN` in `sim/npc.js` (turns over 130 degrees are U-turns).
- **Street cross-section.** `map/streets.js` (gutter, curb, boulevard, sidewalk) is shared by the renderer and the pedestrians; crosswalk positions depend on it and on the asphalt width (which includes parking lanes).
- **Two copies of the lane-join logic.** The router joins lane polylines by rounding the real corner (`_round_corner` / `_blend` in `jev/routing.py`); `joinLanes` in `static/js/map/mapdata.js` mirrors it for NPC paths. Keep them in sync. Naive end-to-start joins make right turns back up.
- **Parking is opt-in.** `World` option `park` (free drives, unless `?park=0`; challenges with `park: true`) makes the autopilot parallel park at the destination and pull out again at the start of the next drive (`sim/parallel-park.js`, `World.park`/`parking`/`parkedIn`). The seeded benchmark and the other challenges never park, so every parking branch must leave the `parkAtGoal` false path exactly as it was. Traffic keeps back from a car parking ahead of it through `World.parkHold` (`sim/npc.js`).
- **Hidden hazards are opt-in.** `World` option `hazards` (free drives, unless `?hazards=0`; challenges with `hidden: true`) makes vehicles standing at the kerb hide pedestrians (`World.sees`), makes road vehicles hide other vehicles and cyclists, with the car waiting to see along the lanes it gives way to (`sim/hidden-traffic.js`), turns on the driven car's blind-spot speed (`blind_spot` in sensing, `sim/blind-spot.js`), and with `stepOuts` lets people step out from between parked cars. With it off nothing is computed and no random stream is drawn from, so the seeded benchmark and the other challenges play out exactly as before; keep it that way.
- **Snow plows are opt-in.** `NpcFleet` option `plows` (free drives, unless `?plows=0`) puts a plow on the main streets while it snows, from its own random stream (`sim/snow-plow.js`); the "Behind the plow" challenge places one itself. The audit's `plow_right_passes` reaches the metrics, and fails a drive, only once a plow has worked in it (`World.plowsSeen`), so the seeded benchmark and the other challenges report exactly as before; keep it that way.
- **Lane closures are opt-in.** `World` option `closures` (free drives, unless `?closures=0`) puts up a lane closure with a zipper merge from its own random stream (`sim/lane-closure.js`); the "Take turns" challenge places one itself. The audit's `merge_cut_ins` reaches the metrics, and fails a drive, only once a closure has stood in it (`World.closuresSeen`), so the seeded benchmark and the other challenges report exactly as before; keep it that way. The driven car has no `id`: closures know it as `EGO_ID` ("ego").
- **Passing cyclists is opt-in.** `World` option `passCyclists` (free drives, unless `?cyclistpass=0`; challenges with `passCyclists: true`) has traffic and the driven car pass a cyclist riding in the lane of a two-way street with one lane each way through the oncoming lane, once it is clear, with the minimum passing distance (`sim/cyclist-pass.js`, `cyclist_pass` in sensing, `pass_cyclist`/`follow_cyclist`). With it off nothing is computed, candidates keep the 1 m `CYCLIST_CLEARANCE_M` rejection (`passes_cyclist_too_close`), and the audit's `close_passes` never reaches the metrics, so the seeded benchmark and the other challenges play out and report exactly as before; keep it that way.
- **Bus lanes are opt-in.** `World` option `busLanes` (free drives, unless `?buslanes=0`; challenges with `busLanes: true`) reserves the lanes of the map's buslanes layer while their hours apply (`sim/bus-lanes.js`, `bus_lane` in sensing, `Route.busLanePolicy`, `NpcPath.busLanePolicy`). Cars enter one only in the last `BUS_TURN_M` (50 m) before a right turn, or to park or pull out at the curb; buses use it. The audit's `bus_lane_driving` (metres, in the lane the car is actually in) reaches the metrics, and fails a drive, only once a bus lane has been in effect where the car was (`World.busLanesSeen`). Hours use `world.clock.hour` and `weekday` (Monday = 0, the default), as turn restrictions do; with no clock no lane is in effect. With it off nothing is computed and no random stream is drawn, so the seeded benchmark and the other challenges play out and report exactly as before; keep it that way.
- **Traffic calming is opt-in.** `World` option `calming` (free drives, unless `?calming=0`; challenges with `calming: true`) has traffic and the driven car slow for the speed humps, tables, cushions and bumps of the map's calming layer (`sim/traffic-calming.js`, `traffic_calming` in sensing, which also caps `snap.limit`), and draws them and the cars riding over them (`render/traffic-calming.js`). The audit's `hump_hits` reaches the metrics, and fails a drive, only once the car has crossed a device (`World.calmingSeen`), so the seeded benchmark and the other challenges play out and report exactly as before; keep it that way.
- **Scramble crossings are opt-in.** `World` option `scrambles` (free drives, unless `?scramble=0`; challenges with `scrambles: true`) sets module state in `sim/signals.js` (`setScrambles`), like the weather's grip: `MapData` keeps a `scramblePlan` beside `plan` for each signal in the map's scrambles layer, and `planOf` picks it only while scrambles are on. A scramble's all-walk is exclusive (`pedPhase` gives every group the all-walk), people cross diagonally there, and there is no right turn on red (`isScramble`, in sensing, `NpcFleet.rightOnRed` and the audit). With it off every signal runs and every pedestrian walks exactly as before; keep it that way.
- **Garbage trucks are opt-in.** `NpcFleet` option `collection` (free drives, unless `?collection=0`) puts a truck to work on the quiet streets by day, from its own random stream (`sim/collection-truck.js`); the "Collection day" challenge places one itself. A truck standing at a stop is a record in `world.doubleParked` (`truck: true`) for as long as it stands there, so everyone treats it as a double-parked van, waiting `TRUCK_WAIT_M` back and going round only once no worker is in the street (`crewInRoad` in `wayRound`). Its crew are pedestrians with `crew` set. The audit's `crew_close_passes` reaches the metrics, and fails a drive, only once a truck has stopped to collect in it (`World.collectionSeen`), so the seeded benchmark and the other challenges report exactly as before; keep it that way.
- **School crossing guards are opt-in.** `World` option `guards` (free drives, unless `?guards=0`; challenges with `guards: true`) staffs marked mid-block crosswalks in school zones while `inEffect` holds (`sim/crossing-guard.js`). Guards and children are pedestrians (`guard` / `child`); their manager moves them until children reach the far sidewalk. Everyone, cyclists too, stops for the raised STOP sign until the guard and every child are off the roadway. Stop obligations are captured when the sign rises and shared by sensing, traffic and audit. The audit's `guard_violations` reaches the metrics, and fails a drive, only once a guard has stood out in it (`World.guardsSeen`). With it off nothing is computed and no random stream is drawn, so the seeded benchmark and the other challenges play out and report exactly as before; keep it that way.
- **Ontario pedestrian crossovers are opt-in.** `World` option `pxo` (free drives, unless `?pxo=0`; challenges with `pxo: true`) enables the Ontario maps’ separately stored `map.pxos` from the crossings v2 sidecar. `sim/pxo.js` holds traffic and the driven car until every pedestrian clears the whole roadway, including the far curb. PXOs are added to the crowd only while enabled, so with it off no crossing geometry, random stream or existing challenge changes. The audit’s `pxo_early_goes` reaches the metrics and fails a drive only once a nearby PXO has been occupied (`World.pxoSeen`); keep it that way. Legacy crossings v1 sidecars remain readable; never bump the street pack for a crossing-layer change.
- **High beams are opt-in.** `World` option `highBeams` (free drives unless `?highbeams=0`; challenges with `highBeams: true`) adds beam actuation every decision cycle, `headlights` sensing and model answers, and longer forward sight on dark unlit streets (`sim/high-beams.js`). Rules and the cautious agent dip for oncoming traffic within 150 m, following within 60 m, fog, snow and lit streets; sensing includes a reaction margin. NPC dipping and flashes are render-only. The audit’s `glare_seconds` reaches metrics and fails above 0.8 s only after night driving with the feature on (`World.highBeamsSeen`). With it off nothing is computed and no random stream is drawn, so the seeded benchmark and other challenges play out and report exactly as before; keep it that way. Compact trace folding must compare beam choices.
- **Turn restrictions are opt-in.** `World` option `restrictions` (free drives, unless `?restrictions=0`; challenges with `restrictions: true`) applies the OSM via-node turn restrictions layer to route requests and NPC successor choices (`sim/turn-restrictions.js`). Conditional signs use local `world.clock.hour` and `weekday` (Monday=0, the default); the app clock advances the weekday at midnight. Sensing reports `turn_restriction`; the audit’s `illegal_turns` reaches metrics and fails a drive only once a restriction has applied (`World.restrictionsSeen`), so the seeded benchmark and the other challenges play out and report exactly as before; keep it that way.
- **Overnight flashing signals are opt-in.** `World` option `nightFlash` (free drives, unless `?nightflash=0`; challenges with `nightFlash: true`) selects strictly separated road-class groups deterministically from the pack (`sim/night-flash.js`), from 23:00 inclusive to 05:00 exclusive on `world.clock.hour`. No clock means no flashing. Main-street amber has a 20 km/h caution ceiling and yields to people and traffic already in the junction; side-street red reuses a two-way stop, never the all-way queue. Outages take precedence; flashing suppresses advance greens, scrambles and right-on-red. Signals use module state (`setNightFlash`), reset by each World and replay restore. The audit counts missed red stops as `stop_signs_run` and priority violations as `failed_to_yield`, only on encountering flashing operation (`World.nightFlashSeen`). With it off no selection, random draw or existing benchmark/challenge behavior changes; keep it that way.
- **Contraflow cyclists are opt-in.** `World` option `contraflow` (free drives, unless `?contraflow=0`; challenges with `contraflow: true`) puts cyclists from their own random stream on the map's contraflow layer, riding against the one-way at the driver's left and stopping for what faces their way (`sim/contraflow.js`, `World.contraflow`). They are not in `world.npcs`: `world.obstaclesNear` adds them, and traffic, sensing (`contraflow_cyclist`) and the forward sims meet them through the one conflict test `riderConflict` (wait short of the junction for one coming out of a street being entered; move over, and stop where that leaves less than the minimum passing distance, for one coming the other way). The audit's `contraflow_conflicts` (cutting one off, also `failed_to_yield`, or meeting one too close) reaches the metrics, and fails a drive, only once one has ridden near the car (`World.contraflowSeen`). With it off nothing is computed and no random stream is drawn, so the seeded benchmark and the other challenges play out and report exactly as before; keep it that way.
- **Left turns on red are opt-in.** `World` option `leftOnRed` (free drives, unless `?leftonred=0`; challenges with `leftOnRed: true`) permits a left from a one-way approach onto a one-way exit in the supported provincial map regions, after a full stop in the leftmost lane and yielding to pedestrians and traffic from the right. It shares right-on-red sensing, stop memory, gap checks and audit; Québec, scrambles and signed turn bans never qualify (`sim/left-on-red.js`). The reviewed city bounds fail closed for new maps; extend them only after checking provincial law. `World.leftOnRedSeen` records a legal opportunity; no new metric is added. With it off nothing is computed and no random stream is drawn, so the seeded benchmark and other challenges play out and report exactly as before; keep it that way.
- **Red-turn signs are opt-in.** `World` option `redTurnSigns` (free drives unless `?redturnsigns=0`; challenges with `redTurnSigns: true`) applies the restrictions sidecar's separate `red_turns` list (`sim/red-turn-signs.js`). These bans prohibit a turn only on red; never feed them into ordinary routing restrictions. Sensing, NPCs, left-on-red eligibility and the actual-exit red-light audit share this policy. The audit captures active bans at line crossing, so a schedule changing mid-turn cannot change the verdict. No new metric is added. Only Toronto's sidecar currently contains mapped signs. With it off, existing challenges and benchmarks retain their previous red-turn behavior.
- **Amber-light decisions are opt-in.** `World` option `amberLights` (free drives unless `?amberlights=0`; paired challenges with `amberLights: true`) shares the first-visible-amber stop decision between sensing, candidates, local drivers, NPCs and the line-crossing audit (`sim/amber.js`). Stopping distance includes reaction, actuator lag and grip; the decision is latched per physical approach and signal phase on the vehicle, so checkpoints preserve it. Clearing speed is capped at the observation speed; pedestrians, traffic and blocked exits still take priority. An entry on red remains prohibited, while a car already across the line clears the junction. `amber_lights_run` reaches metrics only after an observed amber (`World.amberLightsSeen`). With the feature off, previous challenges and benchmark behavior and metric shapes remain unchanged.
- **Following distance is opt-in.** `World` option `followingDistance` (free drives unless `?followingdistance=0`; the "Brakes ahead" and "Make room" challenges) shares grip/response-based gap targets and safe speeds through `sim/following.js`, sensing, predictions, local drivers, ordinary motor traffic and coaching. Keep special plow/cyclist/emergency gaps in force. Coaching grants five seconds of recovery when a newly encountered leader moves sideways into the car's path, once per leader per drive, and checkpoints preserve that state. With it off, no policy work or random draws occur and existing benchmark/challenge behavior and report shapes stay unchanged.
- **Red-light runners are opt-in.** `World` option `redRunners` (free drives unless `?redrunners=0`; challenges with `redRunners: true`) lets an ordinary traffic car that could stop for an amber commit, now and then, to running the late amber or fresh red (`sim/red-light-runner.js`, its own random stream, drawn once per approach, at most one commitment every 30 s). A runner holds the speed it had, never commits into an occupied junction box, gives up while it can still stop if someone gets there first, and keeps every other leader, crosswalk and box check, so it never drives into anyone already in its path. `runnerThreat` is the one test, shared by sensing (`red_light_runner`), candidates (`wait_for_runner`, rejection `enters_ahead_of_red_light_runner`), Rules, the cautious agent, the model wording, traffic waiting on a green and the audit: a vehicle crossing the observer's way on a red or amber that cannot stop before its line (`sim/amber.js` stopping distance, unless visibly braking hard enough) or has entered the junction on one. The audit's `fresh_green_conflicts` (entering on green while one is in sight, after the car could have stopped for it) reaches the metrics, and fails a drive, only once a runner has committed within 120 m of the car (`World.redRunnersSeen`). With it off nothing is computed and no random stream is drawn, so the seeded benchmark and the other challenges play out and report exactly as before; keep it that way.
- **Sun glare is opt-in.** `World` option `sunGlare` (free drives unless `?sunglare=0`; challenges with `sunGlare: true`) computes the sun from `world.clock` (`hour`, and `day` of the year and `utc_offset` only when the clock has them) and the pack's origin (`sim/sun-glare.js`). A clock without `day` keeps the sky's late-September sun (`sunAngles` in `sim/speed-zones.js`) so the sky, darkness and glare agree; the sky draws a challenge's date only when its clock has one. Glare applies on a clear, daylit road when the sun is 0–20° up and within 30° of a vehicle's heading. The World installs `visibility.glare`, which shortens only the driven car's sight towards the sun; sensing (`sun_glare`, capping `snap.limit`), traffic (a speed cap) and the audit share `glareFor`/`glareCeiling`, built on `comfort()`. `glare_speeding_seconds` reaches metrics and fails a drive above 1 s only after glare has applied (`World.sunGlareSeen`). With it off nothing is computed, nothing is random, the clock keeps its old shape, and the seeded benchmark and other challenges play out and report exactly as before; keep it that way.
- **Driveway reversers are opt-in.** `World` option `driveways` (free drives, unless `?driveways=0`; challenges with `driveways: true`) has a car parked nose-in in a driveway of the map's driveways layer near the car's route back out now and then, from its own random stream (`sim/driveway-reversers.js`, `World.driveways`): it creeps across the sidewalk, looks, backs into the near lane on the shared car model in reverse and hands over to `NpcFleet` as an ordinary car. Reversers are not in `world.npcs`: `world.obstaclesNear` adds them, `World.sees` lets parked cars hide them with hazards on, and sensing (`reversing_vehicle`), candidates (`yield_to_reversing`, `passes_reversing_vehicle_too_close`, forward sims predicting them along their way out with `reverserBoxAt`), traffic and the audit share the one conflict test `reverserConflict`. With the option on, parked cars across a driveway are removed when the world is built. The audit's `reversing_conflicts` reaches the metrics, and fails a drive, only once one has backed out near the car (`World.drivewaysSeen`). With it off nothing is computed and no random stream is drawn, so the seeded benchmark and the other challenges play out and report exactly as before; keep it that way. `reverseLamps` is render-only.
- **Coordinates.** Sim is x east, y north, meters; headings are radians counter-clockwise from +x; `lateral > 0` means right of travel (the right normal is `(sin h, -cos h)`). Three.js is `(x, z, -y)`. In meshes placed with `rotation.y = heading`, local +x is forward and local +z is the right side.
- **Ground rendering order.** Coplanar ground layers (grass, sidewalk, curb, asphalt, markings) are drawn with `depthTest`/`depthWrite` off in fixed `renderOrder` (`LAYER` and `groundLayer()` in `render/scene.js`), with the sky first; roundabout islands are `islandCurb`/`island`, above asphalt. Speed humps and the like rise above the ground and are depth-tested, drawn after the markings (`render/traffic-calming.js`). Anything placed below y = 0 breaks this. Overlays are transparent and depth-tested so cars hide them.

**Jev prompting.** Jev takes question wording literally; criteria must say *when* an option is correct. Weather, roundabout, cyclist, and pedestrian clauses were added on the `sim-realism` branch without a live check. `motion` is only asked when `needsMotionQuestion` holds, and `vector` only with two or more eligible candidates; everything else is answered locally. After changing wording in `state.js`, run `scripts/verify_jev.py`.

**Benchmark** (`static/js/bench/`): `scenarios.buildSuite` (seeded, routes via `/api/route`), `runner.runScenario` / `setupScenario` (also used by the app's `/?replay=1`), and `metrics.DriveMetrics`. Pass/fail rules live in `failures()` (collisions, red lights, stop signs, failures to yield, off road). Bench runs take a `weather` option. Runs are stored by `server.py` under `data/runs/`, which is gitignored, so a baseline has to be added with `git add -f`.

## Gotchas

- Editing a Python file with an in-place substitution that keeps the file size, inside the same second, can leave a stale `__pycache__/*.pyc` that Python still trusts. Delete `__pycache__` if a change seems to have no effect.
- NPC colors and car body styles are render-only. Nothing in sim or brain reads them.
- In Node tests, never pass sim objects (World, Route, MapData, vehicles) to `assert`; assert on primitives such as ids, counts and booleans. A failing assert on one makes Node print the whole object graph, which has used 70–200 GB of memory on a 16 GB Mac, and `--max-old-space-size` does not stop it. Run heavy checks one at a time; the full Playwright suites run in CI.
- Node test scripts that build an `Autopilot` never exit on their own; end them with `process.exit(0)`. Run `scripts/test_*.mjs` with Node 22, as CI does; Node 24 rejects `--experimental-default-type`.
- `window.__bench.run` saves to `data/runs/` unless you pass `save: false`. For before/after benchmarks, check that the before tree really matches its commit (`diff -r` against a fresh `git archive`) and that its results reproduce the previous record; WebKit can expose timing bugs V8 misses.
- Saved arena runs count against the 9 MB `MAX_HISTORY_BYTES` cap in `static/js/lab/history.js`. Since compact decisions are folded together (`static/js/lab/trace.js`), two runs of every challenge with Rules and the cautious agent, measured in Node (2026-11-06) by `scripts/test_drive_lab.mjs`, take 66.0% (6,228,426 bytes) with 50 challenges ("Into the sun" adds 2.0%, "Reverse lights" 1.4%, "Fresh green" 0.7%, "Space to react" adds 1.9%, "Left on red" adds 1.3%, "Dip your lights" 1.2%, "Both ways" 0.6%, "After midnight" 1.3%, "No left turn" adds 2.4%, "Stop for the guard" 1.5%, "Wait for the far curb" 1.0%, "Buses only" 0.8%, "Over the humps" 0.9%, "All walk" 1.5%, "Collection day" 1.3%, "Give them room" 0.7%, "Take turns" 1.5%, "Behind the plow" 0.8%, "Blind left" 2.0%; 98.2% with 26 before folding). Measure again after adding a challenge or more to each decision record.
- After changing candidates or sensing, rerun `scripts/build_jev_fixtures.mjs --check` (see `docs/project-reference.md`).
- Keep benchmark worktrees out of `/tmp`.

## Decisions

- Ask before adding any dependency, tool or service.
- New maps are Canadian cities. LLM drivers use a generic OpenAI-compatible endpoint. A Claude brain is deferred; keep the brain interface open for it.

  repository docs; do not store them in agent auto-memory or machine-local notes.
- `CLAUDE.md` contains only `@AGENTS.md`. Shared hooks, scripts and settings
  belong in tracked files. Do not ignore instruction files or shared settings;
  ignore only machine-local settings and agent worktrees.
